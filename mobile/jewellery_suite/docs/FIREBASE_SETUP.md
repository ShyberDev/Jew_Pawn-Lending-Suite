## 1. Sign the CLI in (needs your browser)

```bash
npx -y firebase-tools@latest login --no-localhost
```

Paste the code it prints into the browser page it opens. Confirm with:

```bash
npx -y firebase-tools@latest login:list
```

## 2. Point the repo at the project

```bash
npx -y firebase-tools@latest use jewellery-suite--cloud
```

`.firebaserc` in the repo root already names this project.

## 3. Register the Flutter app (once)

```bash
npx -y firebase-tools@latest apps:list --project jewellery-suite--cloud
```

If `com.shyberdev.jewellery_suite` is not listed:

```bash
npx -y firebase-tools@latest apps:create ANDROID "Jewellery Suite" \
  --package-name com.shyberdev.jewellery_suite \
  --project jewellery-suite--cloud
```

Note the **App ID** it prints (`1:…:android:…`). Already done:
`1:1075854501747:android:b47726cc9cbfba996fc706`.

## 4. Download the config — this is the step the app waits for

```bash
npx -y firebase-tools@latest apps:sdkconfig ANDROID <APP_ID> \
  --project jewellery-suite--cloud > android/app/google-services.json
```

`android/app/build.gradle.kts` applies the `google-services` plugin **only when
that file exists**, so no build breaks before it is there. Nothing in the file
is a secret (it is embedded in the APK either way); it belongs in the repo so
every build targets the same project.

## 7. Google’s Web client ID (do not skip)

`google_sign_in` on Android needs the **Web** client ID as `serverClientId`; the
Android client alone returns no usable ID token.

Firebase console → Authentication → Google → **Web SDK configuration** → copy
the **Web client ID** (`…apps.googleusercontent.com`).

Build/run with it:

```bash
flutter run --dart-define=GOOGLE_WEB_CLIENT_ID=<web-client-id>
flutter build apk --release --split-per-abi \
  --dart-define=GOOGLE_WEB_CLIENT_ID=<web-client-id>
```

Without the define the button says so instead of failing silently.

## 8. Create the database and deploy the rules

```bash
npx -y firebase-tools@latest firestore:databases:create "(default)" \
  --edition=standard --location=asia-south1 --project jewellery-suite--cloud

npx -y firebase-tools@latest deploy --only firestore:rules \
  --project jewellery-suite--cloud
```

`firestore.rules` is deny-by-default and shop-scoped:

- `users/{uid}` — that person only.
- `shops/{shopId}` — the owner can always read its own document, even before
  it exists (that is what lets a brand-new account create its shop on the first
  sync); members read shared shops; only the owner edits.
- `shops/{shopId}/{collection}/{docId}` — members read/write, owner deletes.
  Every write must carry `updated_at`.
- Everything else — refused.

## Firestore live sync — what is mirrored

`lib/features/authentication/cloud/cloud_sync.dart` keeps these tables in step
between phones signed in to the same account:

| Local table | Firestore path | Rule |
| --- | --- | --- |
| `jewellery_stock_movements` | `shops/{shopId}/stock_movements/{client_uuid}` | append-only, never replaced |
| `jewellery_worker_orders` | `shops/{shopId}/worker_orders/{client_uuid}` | last write wins on `updated_at` |
| `jewellery_worker_txns` | `shops/{shopId}/worker_txns/{client_uuid}` | last write wins on `updated_at` |

`shopId` is the signed-in account's uid: every phone uses the **same** Firebase
account. Sharing one shop between different accounts needs an invite flow and
is not built.

A stock movement is appended on exactly one phone and keyed by `client_uuid`,
so two phones cannot apply it twice — the stock position converges even though
invoice headers still reconcile through the existing server sync.

Known limits, chosen for this phase:

- **No deletions** are mirrored: a row removed on one phone stays on another.
- **Invoice headers and payments are not mirrored**, so money totals still come
  from the shop server (`SyncService` / `ApiClient`). Firestore is the stock and
  worker transport only.
- **Clocks:** ordering uses each row's own ISO-8601 stamp, so a phone with a
  badly wrong clock can make an older worker edit win. Fix the phone's date if
  a worker record looks stale.

Status and a **Sync now** button live on the Cloud account screen; the mirror
also starts automatically at launch.
